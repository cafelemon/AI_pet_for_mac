## Workflow

1. Mark the target state `in_progress` here before any processing starts.
2. Run `white-bg-video-matting` on the current source video with the state's initial parameter profile.
3. Review the raw white-skill QA outputs first and confirm the full intended silhouette plus all critical props remain intact.
4. Project the transparent result into the runtime `1536x1728` canvas with the state's current layout preset.
5. Review projected QA on magenta, black, and gray backgrounds.
6. If QA fails, do up to 2 tuning rounds within scope:
   - Missing body or props: raise `alpha_expand`, lower `erode_size`, or relax runtime crop/scale.
   - White fringe or residue: lower `alpha_expand`, raise `erode_size`, or tighten runtime cleanup.
7. When QA passes, replace `assets/webm/<state>/<state>_loop.webm`, regenerate fallback keyframe and standard QA outputs, sync `data/config/states.config.json` `durationMs` to the final WebM, and run `python3 scripts/asset_check.py --webm-strict`.
8. If QA still fails after 2 tuning rounds, mark `failed_continue`, record the exact failure, and continue to the next queued state immediately.
9. Temporary inspection override note: `failed_continue` previews were briefly finalized into runtime assets so they could be inspected in the real app. After review, `sleep` and `idle_reading` were rolled back to the original shipped runtime asset/keyframe while keeping their `.matting_work` evidence and exact QA defect notes. `error` remains live as the failed preview candidate for inspection.
