# Version Naming Rule

更新时间：2026-05-29

## 基本格式

版本号格式：`VMAJOR.MINOR.PATCH`

示例：

- `V1.0.0`
- `V1.1.0`
- `V1.1.1`
- `V2.0.0`

npm/package 版本号不带 `V` 前缀，例如 `1.0.0`。

## 三段含义

### MAJOR：大版本

第一个数字代表大版本迭代。只有当产品形态、核心架构或差异化方向发生明显变化时才升级。

升级示例：

- 从本地桌宠运行时升级为 AI companion kernel：`V1.x.x` -> `V2.0.0`
- 从单用户本地应用升级为多 agent/project session 平台：`V2.x.x` -> `V3.0.0`
- 架构从单应用正式拆为可发布 client/server/package 生态：可考虑大版本

### MINOR：功能/板块版本

第二个数字代表新增或修改一个明确板块、功能点、profile、协议层或主要工作流。

升级示例：

- 新增 AI/Agent 接入层：`V1.0.0` -> `V1.1.0`
- 新增用户交互动作为可运行功能：`V1.1.0` -> `V1.2.0`
- 新增 profile package 导入：`V1.2.0` -> `V1.3.0`
- 新增声明式插件系统：`V1.3.0` -> `V1.4.0`

### PATCH：修复/小迭代

第三个数字代表 bug fix、小体验优化、文档补充、配置修正、素材小修。

升级示例：

- 修复某个 action fallback 路径。
- 修正 README 或 PRD 的描述。
- 调整 cooldown 默认值。
- 修复一条 validator 误判规则。
- 补一个遗漏的 progress doc 行。

## 当前规则

- 当前版本：`V1.3.0`
- 基线冻结版本：`V1.0.0`
- 当前功能版本：`V1.2.0`，主题为用户交互动作补齐
- 当前功能版本：`V1.3.0`，主题为本地 Profile Package
- 不因为单个素材替换升级 `MINOR`，除非它形成新的可用动作板块或 profile 能力
- 不因为文档错别字、注释、轻微样式调整升级 `MINOR`
- 任何破坏兼容的协议改动，在 `V1.x` 阶段要记录迁移说明；稳定后再考虑 `V2.0.0`

## 发布命名

推荐 tag：

- `v1.0.0`
- `v1.1.0`
- `v1.2.0`

推荐 release title：

- `V1.0.0 - Local Runtime Baseline`
- `V1.1.0 - AI Agent Protocol`
- `V2.0.0 - AI Companion Kernel`

## 冻结定义

冻结某版本意味着：

- 文档明确该版本范围。
- package 版本号与版本记录一致。
- 当前可用能力不再被无意改名、删除或重做。
- 后续改动必须按 `MINOR` 或 `PATCH` 归档。

冻结不意味着：

- 不允许继续开发。
- 不允许修复 bug。
- 不允许新增 profile 或动作。
- 不允许重构。只是重构必须有版本语义和验收边界。
